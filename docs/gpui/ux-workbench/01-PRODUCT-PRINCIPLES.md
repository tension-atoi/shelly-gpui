# 01 — Product Principles: Professional Native Package Workstation

## What Shelly Is Not
- **Not a web dashboard**: Shelly avoids generic web-like cards, bloated paddings, and floating cards with disconnected metadata.
- **Not an app-store toy**: Shelly avoids infantilizing user interfaces, giant toy icons without technical clarity, and hidden system truths.
- **Not a SaaS control panel**: Shelly avoids low-density metric widgets, vague status pill soups, and ambiguous state badges.
- **Not a pile of pills/chips**: Filters and query controls must behave as integrated engineering tools with deliberate visual hierarchy.

## What Shelly Is
Shelly is a **professional native package-management workstation** built for Linux engineers and power users:
1. **Ergonomics**:
   - Zero unnecessary mouse travel.
   - Primary search and filters remain immediately accessible without scrolling or hidden menus.
   - Dense, high-information-density layouts where every pixel serves clarity.
2. **Ease of Use**:
   - Keyboard navigable throughout (Tab, Space, Enter, Escape).
   - Clear visual focus states and tactile feedback.
   - Predictable layout behavior across window resizes.
3. **Beauty**:
   - Monochromatic precision with deliberate semantic accent colors.
   - Clean structural grid alignment and crisp borders.
   - Restrained, intentional motion that respects user accessibility settings.

## Strict Pane Roles
- **Results List is the Primary Canvas**: The left pane is the dominant working surface where packages are found, compared, and managed.
- **Inspector is a Secondary Diagnostic Panel**: The inspector exists to examine package details, dependencies, files, and build scripts. It must never dominate, engulf, or occlude the primary canvas.
